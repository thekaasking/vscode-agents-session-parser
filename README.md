# session-parser

A lightweight Python toolkit for parsing exported GitHub Copilot agent session debug logs into a structured, human-readable summary.

This project was built to assist in parsing logs as part of an MSc thesis analyzing (sub)agent behavior, extracted from very large, trace-like debug logs produced by VS Code's Copilot agent sessions.

This project takes either:

- a Copilot session export zip file, or
- a pre-extracted session directory

and turns the raw JSONL event stream into a single JSON object plus optional Markdown/CSV outputs for review, analysis, and reporting.

## What it does

The parser reads exported session data such as `main.jsonl` and `runSubagent-*.jsonl`, then aggregates:

- user prompts and final responses
- per-turn timing data
- LLM token usage and cache-hit rates
- tool-call counts, durations, and errors
- subagent invocations and nested session metadata
- reconstructed file artifacts created or modified by the agent
- terminal command summaries
- discovered agents, skills, and instructions

The result is a JSON document suitable for:

- automated analysis
- dashboards and reports
- debugging long AI agent runs
- reviewing summaries of tool usage and cost

## Supported inputs

The parser accepts either of these:

1. a `.zip` session export generated by GitHub Copilot debug-log export
2. an extracted session folder with the same internal files

Typical inner files include:

- `main.jsonl`
- `runSubagent-*.jsonl`
- `title-*.jsonl`
- other metadata JSON files from the Copilot export

## Retrieving a debug log export

Session debug logs are not written by default. First enable the setting:

```text
github.copilot.chat.agentDebugLog.fileLogging.enabled
```

With logging enabled, sessions are written to:

```text
%APPDATA%\Code\User\workspaceStorage\<workspace-id>\GitHub.copilot-chat\debug-logs\
```

There are two ways to get from there to a session export:

1. **Browse the folders directly.** Find your workspace's folder under `workspaceStorage` (sort by most recent modification time to identify the right `<workspace-id>`), then do the same to find the right session folder inside `debug-logs\`.
2. **Use the command palette.** Run `Developer: Open Agent Debug Logs` (Ctrl+Shift+P), click the session you want in the panel, then use the download-style button in the top-right corner to export it. This prompts you to save a `.zip` file — the filename it suggests is the session id.

Either the exported `.zip` or the raw session folder can be passed directly to this parser.

- Python 3.14 (see `.python-version`)
- No third-party dependencies

## Quick start

### CLI usage

This project has no third-party dependencies (standard library only). No packaging/build files are included; to run the CLI, clone the repo into a folder named `session_parser` (so it can be imported as a package), then run it from the parent directory:

```bash
git clone https://github.com/thekaasking/vscode-agents-session-parser session_parser
python -m session_parser <path-to-session>
```

Examples:

```bash
python -m session_parser session.zip --pretty
python -m session_parser session.zip --out stats.json
python -m session_parser session.zip --output-dir ./out/session-report
python -m session_parser extracted/session-dir/ --baseline
```

### Output modes

The CLI supports three modes:

- print JSON to stdout
- write JSON to a file with `--out`
- write a bundle of artifacts to a directory with `--output-dir`

When using `--output-dir`, the tool produces files like:

- `stats.json`
- `prompt.md`
- `final_response.md`
- `tool_calls.csv`
- `subagents.csv`
- `tool_errors.csv`
- `terminal_commands.csv`
- reconstructed artifact files from create/apply_patch events

## Python API

```python
from session_parser import parse_session, SessionSource

result = parse_session("session.zip")
print(result["interaction"]["initial_prompt"])
print(result["tokens"]["all_agents"]["input"])
```

You can also work directly with the session source abstraction:

```python
from session_parser import SessionSource

with SessionSource("session.zip") as src:
    for name in src.list_jsonl():
        print(name)
```

## Output structure

The parsed session is a single dictionary with these main sections:

- `_meta`: basic session metadata
- `context`: loaded agents, skills, and instructions
- `interaction`: prompts and final responses
- `timing`: wall time and per-turn timing
- `tokens`: token counts for main agent and all agents
- `tool_calls`: tool usage stats and errors
- `artifacts`: list of discovered file operations
- `artifact_contents`: reconstructed final content of created/edited files
- `subagents`: subagent summaries and nested output
- `main_turns`: per-turn details for the main agent

A representative structure looks like:

```python
{
  "_meta": {
    "session_id": "...",
    "agent_name": "Copilot",
    "model": "...",
    "reasoning_effort": "medium",
    "is_baseline": False,
  },
  "interaction": {
    "user_turn_count": 3,
    "initial_prompt": "...",
    "final_answer": "..."
  },
  "tokens": {
    "main_only": {"input": 12000, "output": 3000, "cached": 5000},
    "all_agents": {"input": 25000, "output": 6000, "llm_calls": 14}
  },
  "tool_calls": {
    "main_agent": {"total": 10, "errors": 1, "by_type": {"read_file": 4}}
  },
  "subagents": [],
  "main_turns": []
}
```

## Internal design

The repo is organized into a few focused modules:

- `__main__.py` — CLI entry point
- `parser.py` — core logic for parsing JSONL session data and aggregating the results
- `io.py` — session source abstraction for zip files or extracted directories
- `helpers.py` — utility functions for JSON decoding, discovery parsing, artifact extraction, and reconstruction
- `writers.py` — export logic for JSON/Markdown/CSV summaries
- `__init__.py` — package exports

## Project status

This project was built for a specific MSc thesis and is no longer under active development as of early June 2026. There are no planned future updates.

It was last tested against session exports produced by VS Code [1.122](https://code.visualstudio.com/updates/v1_122). The Copilot debug-log export format may change in later VS Code releases without a corresponding update to this parser.
